# 08 · 线上数据自进化：从「老师喂养」到「结果驱动」的真·自进化

> 01 篇讲透了现在的自进化机制：老师通过「对话教学 / 实测纠偏 / 工单补充」三条入口喂进样本，沉淀成「样本 + 总纲」，靠上下文注入即时生效。一个更进一步的追问随之而来——
>
> **训练样本现在全靠我们自己（老师）提供。能不能让系统把线上真实对话拿来自动学习，越用越聪明？这才是真正的 AI 自进化。**
>
> 一句话结论：**能，但难点不在「怎么把线上数据拿进来」（trace / metrics_log / 会话历史其实已经把原料存下了），而在「谁来告诉系统这段对话答得好」。真正的自进化 = 从「业务结果信号」反推好/坏对话，而不是拿「AI 自己说得流不流畅」当标准。人不是被去掉，而是从「从零编样本」升级为「审核否决自动候选」——效率放大几十倍，质量闸门保留。**

---

## 一、先看清现状：现在的「进化」信号全部来自老师

01 篇的三条入口，本质都是**人（老师）在提供监督信号**：

| 入口 | 谁给的信号 | 信号可信度 |
|------|-----------|-----------|
| 对话教学 `taught` | 老师主动示范 | 老师说的即为对 |
| 实测纠偏 `refine` | 老师点评某条回复 | 老师说的即为对 |
| 工单补充 `ticket` | 老师回填答不上的问题 | 老师说的即为对 |

代码里也印证：样本入库的 `source` 就这三类，`add_sample` 是唯一的沉淀入口。

```15:24:ai-customer-service/app/services/playbook_service.py
def add_sample(question: str, answer: str, note: str = "",
               source: str = "taught") -> int:
    vector, sig = embedder.embed(question)
    with cursor() as cur:
        cur.execute(
            "INSERT INTO playbook (question, answer, note, source, vector, vec_model) "
            "VALUES (?, ?, ?, ?, ?, ?)",
            (question, answer, note, source, json.dumps(vector), sig),
        )
        return cur.lastrowid
```

**老师教学天然自带「这是对的」这个信号**。要迈向「线上数据自进化」，核心就是回答一个问题：**当没有老师时，好答案的信号从哪来？**

---

## 二、关键判断：线上数据不会自动等于「好数据」

线上对话是**「AI 自己说过的话」**。如果直接把 AI 的回答当正样本喂回去学，会掉进最危险的坑——**自我强化（回声室）**：

```text
AI 答得越顺、越自信的错误
   → 被当成「好样本」挖回来
   → 固化进样本库 / 总纲
   → 下次更自信地重复这个错误
   → …… 错误被不断放大
```

所以本篇最重要的一条原则：

> **别让 AI 拿自己的话当老师。要让「成交 + 客户满意」这类业务结果当老师。**
>
> 监督信号必须来自**对话之外的客观结果**（客户买没买、满不满意），而不是**对话本身的流畅度**。

这条原则决定了下面整条链路的设计。

---

## 三、完整链路：线上对话 → 自动候选 → 人审 → 生效

整体是在 01 篇「示范学习 + 上下文注入」哲学之上，**扩展信号源**，而不是推倒重来。

```text
① 采集   线上 trace / metrics_log / 会话历史(脱敏)
             │
② 信号   给每段对话打「好/坏」标签(结果信号为主)
             │
③ 挖掘   正样本(金对话) + 负样本(短板洞) + 真实问法聚类
             │
④ 提炼   LLM 把金对话提炼成候选样本(问题+答案+套路原因)
             │
⑤ 闸门   候选进「待审区」(source=mined)，老师批量审 → 接受才生效
             │
⑥ 度量   命中率 / 转人工率 / 转化率 前后对比，验证真提升
             │
             └──▶ 回到 ①(闭环，能力单调上升)
```

### ① 采集层：原料你们基本已有

- 完整对话轨迹 `trace`：04 篇里 loop 每步都记了「上下文 / 决策 / 工具结果」；
- 指标流水 `metrics_log`：已记录每轮 `question / hit_kb / handoff`；

```87:93:ai-customer-service/app/services/chat_service.py
def _log_metrics(session_id: str, question: str, result: LoopResult) -> None:
    hit = 1 if (result.kb_hit and not result.handoff) else 0
    with cursor() as cur:
        cur.execute(
            "INSERT INTO metrics_log (session_id, question, hit_kb, handoff) VALUES (?, ?, ?, ?)",
            (session_id, question, hit, 1 if result.handoff else 0),
        )
```

- **先补一件事：入库前脱敏**（手机号、微信号、姓名等 PII）。这是合规红线，不能省。

### ② 信号层：整个方案的胜负手

给每段对话打上「答得好不好」的标签，按可信度从高到低：

| 信号类型 | 具体信号 | 说明 |
|---|---|---|
| **业务结果**（最硬） | 是否留资 / 加微信 / 成交 | 客服最真实的 reward，骗不了人 |
| **显式反馈** | 客户点赞点踩、会话后评分 | 有就用，通常覆盖率低 |
| **隐式负信号** | 同一问题反复追问、中途流失、情绪不满、被迫转人工 | 「答砸了」的高召回信号 |
| **一致性自检** | 回答是否违反铁律/总纲（可让 LLM 当裁判打分） | 防止把违规回答当正样本 |

**核心：用「结果信号」而非「AI 自我感觉」当监督**，从源头堵住第二节说的自我强化。

### ③ 挖掘层：挖两类，价值不同

- **正样本（金对话）**：达成转化 + 无纠偏 + 命中良好的对话 → 提炼成套路候选。
- **短板 / 负样本**：转人工工单、客户不满、重复追问点 → 这些是「该补的洞」，聚类找高频。

> 💡 线上数据**最大的独特价值**：把海量真实问法**聚类去重**，得到客户**真实的措辞与长尾问法**——这是老师在办公室编不出来的。老师写「课程多少钱」，客户实际会说「你先说个数」「到底得花多少才能学会」。这些真实变体，正好补强你们 02 篇讲的语义检索召回（存语义、覆盖长尾）。

### ④ 提炼层：让 LLM 做苦力

用 LLM 把金对话**提炼成候选样本**（问题 + 标准答案 + 套路原因），直接对齐现有 `add_sample(question, answer, note, source=...)` 结构；把负样本聚出的高频未覆盖问题，生成「待老师补充」的工单式条目。

### ⑤ 质量闸门 + 人审：绝对不能省

这是与「纯手工」最大的区别，也是防 garbage-in 的命门：

- 自动候选**不直接进** `playbook` 生效，而是进「待审区」——建议**新增来源标记 `source="mined"`**，与现有 `taught / refine / ticket` 并列，天然复用 `list_samples(source=...)` 的分类管理。
- 老师**批量审核**（接受 / 改写 / 拒绝），只有接受的才走 `add_sample` 正式生效并并入总纲（沿用 01 篇的「状态合并」）。
- 进阶做**影子评估**：候选先不上线，用它离线重跑历史相似对话，看命中率/转化是否提升，再放行。

这样 01 篇引以为傲的三大优势——**状态合并、可回滚、强可解释**——一条不丢：每条自动样本都能追溯到「从哪段真实对话挖来」，可一键删除。

### ⑥ 度量闭环

继续用命中率 / 转人工率曲线（05/02 篇的数据来源），**再加一条转化率**，做前后对比或 A/B，验证「自动进化」确实带来提升，而不是自嗨。

## 四、两个层次的「进化」，与落地顺序

| | 轻量版（推荐先做） | 重量版（后期可选） |
|---|---|---|
| 做法 | 挖真实对话 → 候选样本/总纲 → 人审 → **注入上下文** | 攒够高质量 (问题, 好答案) 后做 **SFT / DPO 微调**，甚至用转化信号做 RL |
| 生效速度 | 秒级、即时 | 小时~天级 |
| 优势 | 保留可解释 / 可回滚，几乎不动现有架构 | 模型内化能力、推理更省 token |
| 代价 | 低 | 高，且丢掉可解释 / 可回滚 |

**建议顺序很明确：先把轻量版的挖掘闭环跑通。** 它和你们现在的哲学完全一致，只是把信号源从「老师手输」扩展到「线上结果反推 + 人审」。等真实高质量样本攒到几千上万条、轻量版收益见顶后，再考虑微调那条重路。**不要一上来就冲微调**——那会丢掉这套架构最珍贵的可解释与可回滚。
