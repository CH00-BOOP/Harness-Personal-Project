# 04 · Agent Loop：一次完整对话的调度流程

> 前几篇里反复出现一个词——**Agent Loop**：01 篇说它让教学「即时生效」，02 篇说检索是它循环里的一步，03 篇说系统提示词是它每轮临时拼装的。本篇把它单独拎出来讲透：**客户发来一句话，到 AI 吐出回复之间，系统内部到底调度了哪些步骤、按什么顺序转、什么时候停。**
>
> 一句话结论：**Agent Loop 不是「一问一答」，而是一个「想 → 决定调不调工具 → 调了就看结果 → 拿着结果再想 → 直到能答」的小循环。大模型是循环里的「大脑」，工具是它的「手脚」，引擎负责调度、回填结果、并卡住边界（最多几步、最多多久），防止它转不停。**

---

## 〇、先建立总体画面：一次对话 = 一个受控的小循环

传统认知里，「问答」是一条直线：`用户问 → 模型答`。

Agent Loop 把这条直线改成了一个**可以中途去「查资料 / 办事」再回来的循环**：

```text
       ┌───────────────────────────────────────────┐
       │                                            │
       ▼                                            │
 ①拼上下文 ─▶ ②大模型决策 ─┬─ 要调工具? ─▶ ③执行工具 ─▶ ④回填结果 ─┘
                          │                （回到②，带着新资料再想）
                          └─ 能答了(final)? ─▶ ⑤输出回复，结束
                                    ▲
                                    │
                          ⑥边界闸门：步数超了 / 超时 ─▶ 强制转人工收尾
```

大模型每转一圈只做**一个二选一的决策**：

- **「我还得先用个工具」** → 引擎去执行工具，把结果塞回上下文，进入下一圈；
- **「资料够了，我可以答了」** → 产出最终回复，跳出循环。

引擎（AgentLoop）本身**不懂业务、不做判断**，它只干三件事：**拼上下文、执行大模型点名的工具、把结果回填**；外加一个「安全员」角色——**卡边界**，不让循环失控。

下面按「一次对话」的时间线，把每一步拆开。

---

## 一、开场：拼出这一轮的完整上下文

对话一进来，引擎先组装一份**消息列表**，作为大模型这一轮能看到的全部内容，顺序是：

```text
[ 系统提示词(本轮临时拼的“工作守则”) ]   ← 见 03 篇：技术流程+铁律+总纲
        +
[ 这个会话之前的历史对话 ]              ← 只保留干净的“用户↔最终回复”
        +
[ 客户当前这句话 ]
```

两个要点：

1. **系统提示词是「每轮新拼」的**，不是从上一轮抄过来的。所以老师中途改了铁律或总纲，这一轮立刻就用上新的（03 篇讲的「即时生效」在这里落地）。
2. **历史对话是「干净版」的**——中间那些「调用工具、工具返回结果」的过程消息**不会**塞进历史（原因见第六节），只留用户说的和 AI 最终答的，避免上下文越滚越臃肿。

---

## 二、核心：大模型每一步的「二选一」决策

上下文拼好，交给大模型。它返回的**不是一段答案，而是一个「决策」**，只有两种类型：

| 决策类型 | 含义 | 引擎接下来做什么 |
|----------|------|------------------|
| **调用工具（tool_call）** | 「我还需要先用某个/某几个工具」 | 去执行这些工具，把结果回填，**回到第二步再问一次** |
| **产出回复（final）** | 「资料够了，这是给客户的话」 | 输出这段回复，**跳出循环** |

除了这两种，决策里还可能带一段 **「思考（thought）」**——模型说明它「为什么这么决定」，这段会被记进轨迹用于可视化（第五节），但不发给客户。

> 这里有个解耦设计值得一提：引擎只依赖一个抽象的「大模型接口」，它只要求对方「给定上下文和可用工具，返回一个决策」。至于背后是本地的离线桩、还是真实的豆包/其它大模型，引擎一概不管——**换模型不用改循环和工具**。这也是为什么项目能在「离线开发」和「上线接真模型」之间无缝切换。

---

## 三、当决策是「调用工具」：执行 + 回填

如果大模型说「我要调工具」，引擎按标准动作处理：

**3.1 可以一次点名多个工具（并行）。** 模型这一步可能同时要求「查套路 + 查课程事实」。引擎会逐个执行。

**3.2 逐个执行，出错也不崩。** 每个工具执行时，万一报错（比如网络异常），引擎**不会让整个对话崩掉**，而是把错误信息本身当成「工具返回结果」回填给模型，让模型自己看到「这个工具没成」，据此改主意（比如改走转人工）。

**3.3 把结果「回填」进上下文。** 这是最关键的一步——工具的返回结果，会以「工具消息」的形式**追加到消息列表里**，然后**带着这份变长了的上下文回到第二步**，让模型重新决策。

用一句话概括这个回填闭环：

```text
模型：“调 套路召回(查‘转行能就业吗’)”
   ↓
引擎：执行 → 拿到 2 条就业样本 → 追加成一条“工具结果”消息
   ↓
模型（再看一遍，现在多了 2 条样本）：
      “这条套路要用案例给信心，我还得调 案例检索” … 或 … “够了，可以答了”
```

**这就是「Loop（循环）」的由来**：调一次工具，上下文就长一截，模型就多一分依据，直到它认为够了为止。02 篇讲的「先查后答」、03 篇讲的「按需调案例/课程」，都是在这个回填闭环里发生的。

引擎还会在这一步**旁路记两个关键信号**，供事后统计与收尾用：

- 调了「套路召回」且捞到了东西 → 标记**本轮命中知识库**（算命中率用）；
- 调了「转人工」→ 标记**本轮转人工**，并记下工单号。

---

## 四、边界闸门：不让循环转不停

大模型偶尔会「钻牛角尖」——反复调工具却始终不给最终答案。引擎作为安全员，设了**两道硬闸门**，任一触发就强制收尾、转人工话术兜底：

| 闸门 | 触发条件 | 收尾动作 |
|------|----------|----------|
| **最多步数** | 循环转了 6 步（默认）还没给出最终回复 | 回一句「这个问题比较复杂，已为您转接人工客服跟进」 |
| **最长耗时** | 单次对话处理超过 30 秒（默认） | 回一句「处理超时，已为您转接人工客服」 |

这两道闸门保证：**无论模型怎么折腾，一次对话都会在可控的步数和时间内结束**，不会卡死、不会无限烧钱。这是「Agent 能放心上生产」的基本盘。

> 注意区分两种「转人工」：
> - **模型主动转**（调用「转人工」工具）——它自知答不了，是**正常的自纠错**（01 篇讲的工单闭环起点）；
> - **引擎被动转**（撞了上面的边界闸门）——是**兜底保护**，属于异常收尾。

---

## 五、全程留痕：每一步都记进「轨迹」

循环的每一步——「拼了什么上下文、模型怎么决策、调了什么工具、工具返回了什么」——都会被完整记进一份**轨迹（trace）**。

它的价值是**可解释、可调试**：出了问题能一眼看出「AI 是在哪一步、基于什么资料、做了什么决定」，而不是面对一个黑盒。这也是本项目反复强调的「强可解释」在运行时的体现——前端可以把这份轨迹可视化成「AI 的思考过程」。

---

## 六、收尾：什么进历史、记哪些账

循环结束、拿到最终回复后，引擎做两件收尾工作：

**6.1 更新会话历史（只留干净的部分）。** 前面说过，中间的「调工具 / 工具结果」这些过程消息**不写进历史**，只把「客户说的」和「AI 最终答的」留下。原因有二：一是下一轮没必要重看这些过程细节，二是避免上下文随对话越滚越大、又慢又贵。

**6.2 记一笔指标账。** 把「本轮是否命中知识库、是否转人工」连同问题写进指标流水表。这就是 02 篇末尾说的**命中率、转人工率**曲线的数据来源——每对话一次，就为「进化可量化」添一个数据点。

## 七、把一次完整对话走一遍（具体例子）

以客户问「转行做开发能就业不」为例，看引擎完整调度一遍（承接前几篇的「就业」样本）：

```text
─── 开场 ───
引擎：拼上下文 = [本轮工作守则(技术流程+铁律+总纲)] + [历史] + [“转行做开发能就业不？”]

─── 第 1 圈 ───
大模型决策：tool_call ──▶ 调「套路召回(‘转行做开发能就业不’)」
引擎：执行 → 捞回“就业”相关样本 2 条 → 回填成工具结果；旁路标记：命中知识库✓
                       （回到大模型，带着这 2 条样本）

─── 第 2 圈 ───
大模型决策：tool_call ──▶ 「这条套路要求用真实案例给信心，且已了解客户背景」→ 调「案例检索」
引擎：执行 → 拿到同类学员案例 → 回填成工具结果
                       （回到大模型，现在样本+案例都在手）

─── 第 3 圈 ───
大模型决策：final ──▶ 产出回复：
      “先别急着下结论，你之前做哪行、想往哪个方向走？……我们有位同背景学员……”
      （守住“绝不承诺包就业”的铁律，先挖背景、拿案例给信心）
引擎：输出回复，跳出循环

─── 收尾 ───
引擎：历史只存 [用户问] + [AI 这句最终回复]（中间两次工具调用不入历史）
      指标记账：命中知识库=是，转人工=否  → 命中率曲线 +1
```

对照本文各环节：

| 环节 | 对应本文 | 这个例子里发生了什么 |
|------|----------|----------------------|
| 拼上下文 | 一 | 守则(每轮新拼) + 历史 + 当前问句 |
| 二选一决策 | 二 | 前两圈选「调工具」，第三圈选「产出回复」 |
| 执行 + 回填 | 三 | 套路召回、案例检索各回填一次，越查资料越全 |
| 边界闸门 | 四 | 本例 3 圈就答完，没撞到步数/超时闸门 |
| 全程留痕 | 五 | 每圈的上下文/决策/工具结果都进了轨迹 |
| 收尾记账 | 六 | 只存干净历史 + 命中率 +1 |

## 八、一句话回答本篇的核心问题

| 问题 | 回答 |
|------|------|
| **Agent Loop 是什么？** | 一个「想 → 决定调不调工具 → 调了看结果 → 再想 → 直到能答」的受控小循环，取代了「一问一答」的直线。 |
| **谁在做决策？谁在调度？** | 大模型是「大脑」，每步做「调工具 / 出回复」二选一；引擎是「调度员 + 安全员」，负责拼上下文、执行工具、回填结果、卡边界。 |
| **工具结果怎么用上？** | 以「工具消息」回填进上下文，带着变全的资料再问一次模型——这就是「循环」的本质，也是 02/03 篇各步骤的发生地。 |
| **怎么防止转不停？** | 两道硬闸门：最多 6 步、最长 30 秒，任一触发就转人工兜底。 |
| **一次对话结束留下什么？** | 干净的会话历史（不含中间过程）+ 一笔指标账（命中/转人工）+ 一份可视化轨迹。 |
