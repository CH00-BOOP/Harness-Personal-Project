# 06 · 套路总纲治理：训练素材越来越多，会不会把总纲撑爆？

> **这篇回答一个具体焦虑**：老师每天都在教、样本库从几十条涨到几千条，那份"从全部样本归纳出来的套路总纲"是不是会越来越长，最后把每一轮的系统提示词撑爆、把模型拖慢拖傻？
>
> **一句话结论**：会爆——**但爆的不是"样本变多"，而是"话题域变多 + 归纳不收敛 + 全量常驻注入"这三件事叠加**。治理它有三招：①归纳即收敛（合并同类、设条数上限）②**分域 + 按需注入**（核心）③冷热淘汰。本篇用一家机构从开业到火爆的完整 case，把这三招从头讲到尾。全篇不写代码。

> 关联阅读：[01 · AI 自进化机制](./01-AI自进化机制-输入转化输出.md)（总纲怎么来的）、[03 · 系统提示词三层拼装](./03-系统提示词-初始长什么样.md)（总纲注入在哪一层）、[05 · 上下文管理](./05-上下文管理架构设计-自建CC式方案.md)（"预算而非容器"的心智，本篇沿用）。

## 〇、先分清两个东西：谁会爆，谁不会

项目里"训练素材"最后变成**两样东西**，它们的成本性质完全不同，治理方式也不同：

| | 样本库（具体） | 套路总纲（抽象） |
|---|------|------|
| 是什么 | 一条条"客户问题 + 标准答案 + 套路原因" | 从**全部样本**归纳出的高层应答心法 |
| 每轮怎么用 | **top-k 语义检索**，只捞最相关的 5 条 | **每轮全量常驻**，塞进系统提示词第③层 |
| 库变大会撑爆吗 | **不会**——库再大也只捞 5 条（项目已实现） | **会**——它是"常驻税"，每轮都在，越长越贵 |

**所以焦虑的正主是"套路总纲"，不是"样本库"。** 样本库那条路，项目早就用 top-k 检索解决了（详见 02 篇）：库从 100 条涨到 10000 条，每轮进窗口的还是最相关那 5 条，纹丝不动。

真正要治的，是这份**每一轮都在场**的总纲。下面全篇围绕它。

---

## 一、总纲到底会不会"线性膨胀"？——关键认知

很多人的直觉是："样本 10 条 → 总纲 8 条；样本 1000 条 → 总纲 800 条"，线性爆炸。**这个直觉是错的。**

因为总纲不是样本的"堆叠"，而是样本的"**归纳提炼**"。归纳的本质是**求共性、去重复**：

- 你教了 50 条关于"客户问价怎么办"的样本（问法各异：多少钱、报个价、学费贵不贵、能优惠吗……），
- 它们背后其实是**同一条心法**："别正面直答价格，先挖需求塑造价值、引导对接班主任"。
- 归纳后，这 50 条样本 → 总纲里**still 就那 1~2 条原则**。

所以总纲的增长曲线，不该是"线性"，而该是**对数级**——样本翻十倍，总纲可能只多几条：

```text
样本数     10      120      800      5000
           │        │         │        │
理想总纲   8条 ──▶ 14条 ──▶ 22条 ──▶ 30条    （对数收敛：新话题才长新条目）
失控总纲   8条 ──▶ 60条 ──▶ 300条 ──▶ 爆       （线性堆叠：同类不合并、只加不删）
```

**结论先行**：总纲真正的增长驱动，不是"样本数"，而是"**话题域的数量**"。你新增 500 条同类样本，总纲几乎不长；但你新拓展了"少儿编程""考研辅导""企业内训"三条全新业务线，总纲就会长出三块全新的域。

**这决定了治理的靶心**：不是"限制老师教学"，而是"**控制每轮常驻的域数量**"。记住这句，下面三招都围着它转。

## 二、Case 设定：一家机构从开业到火爆

我们跟着"码上未来 IT 培训"这家机构走三个阶段，看总纲怎么演变、每阶段该上什么手段：

| 阶段 | 样本库规模 | 话题域 | 总纲现状（不治理会怎样） |
|------|------|------|------|
| **① 冷启动** | 12 条 | 就 1 类：转行就业咨询 | 8 条心法，一整块常驻，~500 token，**没问题** |
| **② 成长期** | 120 条 | 涌现 6 类：价格/学历门槛/就业/优惠分期/课程内容/上课形式 | 若只加不并 → 膨胀到 60+ 条，~3000 token，**每轮常驻税爆炸、开始 context rot** |
| **③ 规模化** | 800 条 | 多品类（IT/设计/考公）× 多校区，域裂变到 20+ | 若不分域 → 总纲上万 token，**每轮必爆** |

下面按阶段，一招一招上。

---

## 三、第一招：归纳即收敛（让总纲长成对数曲线）

**适用**：从第②阶段就要开始。**目标**：不让"同类原则"重复堆叠，给总纲一个软天花板。

问题出在哪：项目现在的归纳是"把全部样本交给大模型，让它提炼总纲"。如果归纳的指令不加约束，模型可能会**把每个新话题都单列一条**，越归纳越碎、越归纳越长。

**手段（都在"归纳这一步"的指令里做文章，不改架构）**：

1. **强制合并同类**：归纳时明确要求"讲的是同一条底层原则的，合并成一条，不要因为客户问法不同就拆成多条"。
2. **设每域条数上限**：比如"每个话题域最多保留 5 条最高层的原则；超了就把最相似的两条合并"。给总纲一个硬天花板。
3. **只留"高层策略"，把"具体话术"踢回样本库**：总纲只写"面对询价先挖需求"这种**原则**；"您先别急着看价格，咱先聊聊……"这种**话术**不进总纲，留在样本库里靠 top-k 现召回。（这正是 03 篇"业务铁律用规则、具体话术用示例"的延伸。）

### 输入 → 输出（看收敛效果）

```text
【输入】成长期积累的关于"价格"话题的样本（12 条，问法五花八门）
  "多少钱" / "报个价呗" / "学费贵不贵" / "能便宜点吗" / "有优惠吗"
  / "可以分期吗" / "双十一有活动吗" / "老学员介绍有折扣吗" / ……

【失控归纳（只加不并）】→ 总纲里价格相关长出 8 条，每条对应一种问法  ❌
【收敛归纳（合并同类）】→ 总纲里价格相关就 2 条：                        ✅
  · 面对任何价格/优惠/分期类问题，不正面直答，先确认意向、塑造价值
  · 客户意向明确后，不自己谈价，引导其与班主任一对一对接
```

**效果**：12 条价格样本 → 总纲只占 2 条。这一招让总纲"长得慢"，但它**还是一整块常驻**——话题域一多，2 条 ×N 域还是会累积。所以要上真正的核心手段：分域。

---

## 四、第二招（核心）：分域 + 按需注入

**适用**：第②阶段话题域一多就该上。**目标**：把常驻税从"全量总纲"降到"当前问题相关的一两域"。

这是整篇的核心。思路一句话：**总纲不再是铁板一块每轮全塞，而是拆成按话题分好的几个"抽屉"，每轮先判断"客户这句话属于哪个话题"，只拉开那一两个抽屉。**

### 4.1 把一整块总纲，拆成按域归档的抽屉

```text
【治理前】一整块总纲（每轮全量注入）
┌─────────────────────────────────────┐
│ 22 条心法：价格2 + 学历3 + 就业4 + 优惠3    │  ← 每轮 3000 token 全进窗口
│ + 课程内容5 + 上课形式3 + …               │
└─────────────────────────────────────┘

【治理后】按域拆成抽屉（外部存储，按需取）
[价格域] 2条   [学历门槛域] 3条   [就业域] 4条
[优惠分期域] 3条   [课程内容域] 5条   [上课形式域] 3条
        ↑ 每个抽屉独立存放，平时都不在窗口里
```

### 4.2 每轮怎么判断"该拉开哪个抽屉"——低成本判域

判断"客户这句话属于哪一域"，**不用额外堆一套系统**，直接复用项目已有能力：

| 判域方式 | 成本 | 怎么做 |
|------|------|------|
| **复用 embedding 检索**（推荐） | 几乎为零 | 给每个域写一句描述、算好向量；客户问句向量来了，跟各域描述比相似度，命中最高的 1~2 域。**这跟样本 top-k 检索是同一套向量能力**（02 篇），顺手就能做 |
| **搭主模型顺风车** | 零额外请求 | 本轮 Agent 本来就要调一次模型，让它顺带吐一个"本轮话题域=价格" |
| **关键词兜底** | 免费 | "多少钱/优惠/分期" → 价格域，作为向量的兜底 |

**只注入命中的 1~2 域 + 永远在场的全局铁律**，其余域一律不进窗口。

### 4.3 输入 → 输出（看常驻税怎么降下来）

以阿哲问 **"能便宜点吗？"** 为例：

```text
【判域】"能便宜点吗" → 向量匹配到 [价格域] + [优惠分期域]（命中 2 域）

【治理前·全量注入】系统提示词第③层
  = 全部 22 条总纲                          ≈ 3000 token   ❌ 大量与"价格"无关的就业/课程/学历原则也塞进来了

【治理后·按需注入】系统提示词第③层
  = 全局铁律(4条，永远在场) + 价格域(2条) + 优惠分期域(3条)   ≈ 500 token   ✅
    （学历/就业/课程内容/上课形式 4 个域这轮完全不进窗口）
```

**效果：3000 token → 500 token，常驻税砍掉 ~83%。** 而且更关键的是**信噪比**：模型这一轮眼前只有跟"价格"有关的原则，不会被"就业怎么答""学历门槛怎么答"这些无关心法稀释注意力（这正是 05 篇讲的"避免 context rot"）。

### 4.4 有条永远不能拆走的底线：全局铁律

注意 4.3 里那"4 条全局铁律"是**永远在场**的（比如"绝不主动报价""先确认意向"）。因为铁律是**跨所有话题的红线**，不属于任何单一域，必须每轮常驻。但它**极短、极稳定**（03 篇说过），常驻它成本很低。

> 分域的本质：**把"必须每轮在场的"压到最小（就几条铁律），把"看情况才需要的"（各域心法）挪到按需注入。** 这跟 05 篇 T2 归档"把冷内容搬出窗口"是同一个哲学，只不过这里搬的是"当前话题用不到的域"。

## 五、第三招：冷热淘汰（让总纲不只增不减）

**适用**：第③阶段规模化后。**目标**：治理"域内也在缓慢变胖"和"僵尸原则常年占位"。

即便分了域，单个热门域内部条目也可能慢慢变多，还有些原则可能"教过之后再没被用到"。复用项目**已有的命中统计能力**（01 篇提到系统本来就记命中率/指标）来做淘汰：

- **给每条总纲原则记"命中次数"**：这条原则最近被注入并真正影响回答的频次。
- **长期零命中 → 降级归档**：把它从"常驻/按需注入"移到冷存归档区（不是删，可回溯——沿用 05 篇 T2"搬≠删"的思想）。真有客户又问到，检索还能捞回、必要时重新升回总纲。
- **域内超上限 → 合并最相似**：跟第一招的"条数上限"呼应，热门域内条目超阈值就触发合并。

### 输入 → 输出

```text
【输入】就业域里有一条：
  "面对'能不能进国企'的问题，说明我们有国企定向班……"
  （半年前教的，此后 500 轮对话零命中——业务早不做国企定向班了）

【淘汰】命中次数长期为 0 → 移出就业域、进冷存归档区
【效果】就业域瘦身，常驻/按需注入的内容始终是"活跃、被真正用到"的原则
```

**这一招让总纲成为"活的"**：不是只进不出的垃圾场，而是**热的留、冷的下**，长期维持在一个健康规模。

## 六、把三招串起来：阿哲问"能便宜点吗"的完整一轮

现在看规模化阶段（800 条样本、20+ 域），阿哲这一句问话，从进来到拼出提示词，完整走一遍：

```text
客户："能便宜点吗？"
   │
   ① 判域    问句向量 → 匹配到 [价格域]+[优惠分期域]（复用 embedding，几乎零成本）
   │
   ② 取抽屉  从外部存储只取这 2 个域的总纲（各自早已"归纳收敛+冷热淘汰"过，很精炼）
   │
   ③ 拼守则  系统提示词第③层 = 全局铁律(常驻) + 价格域 + 优惠分期域
   │         其余 18 个域【完全不进窗口】
   │
   ④ 配样本  同时 top-k 检索捞回最相关的 5 条"价格类"具体话术样本（02 篇能力，库多大都只 5 条）
   │
   ⑤ 送模型  第③层总纲 ~500 token（而非全量的上万 token）→ 信噪比高、又快又省
   │
   回复："咱们的投入确实值，先聊聊你的目标，我帮你看最合适的方案，具体优惠可以让班主任给你算……"
        （守住"不主动报价"铁律 + 只看价格相关心法，没被无关域干扰）
```

对照"治理前 vs 治理后"这一轮的账：

| | 治理前（全量常驻） | 治理后（三招齐上） |
|---|------|------|
| 第③层总纲 token | ~上万（20+ 域全塞） | ~500（铁律 + 2 域） |
| 无关信息干扰 | 严重（就业/课程/学历全在场） | 几乎无（只有价格相关） |
| 库继续变大的影响 | 总纲持续变长、越来越爆 | 常驻税基本恒定（只跟"当前几个域"有关，与总库大小解耦） |
| 老师教学体验 | 教多了怕撑爆，束手束脚 | **放心教**，规模由分域+淘汰兜底 |

**最关键的一行是第三行**：治理后，每轮的常驻税**只跟"当前问题涉及的一两个域"有关，跟"总库有多大"彻底解耦**——这才是"库涨到几千条也不怕"的根本原因。

## 七、和项目已有机制的关系（不是另起炉灶）

这三招几乎全是**复用现有能力**，不是新造轮子：

| 治理手段 | 复用了什么现成能力 |
|------|------|
| 样本不撑爆 | **已实现**：top-k 语义检索（02 篇），库多大都只召回 5 条 |
| 判域 | 复用**同一套 embedding 向量能力**（02 篇），给每域一个描述向量即可 |
| 归纳收敛 | 只改**归纳那一步的指令**（01 篇的"重新归纳"流程），加"合并同类+条数上限" |
| 进化不回退 | 复用**状态合并**（01 篇）：分域/淘汰时保留老师手改过的原则 |
| 冷热淘汰 | 复用**已有的命中率/指标统计**（01 篇），加一个"域内命中计数" |
| "搬≠删"归档 | 复用 **05 篇 T2 归档思想**：冷域/冷原则移到归档区可回溯 |

> 一句话：**治理总纲，本质是把"上下文是预算不是容器"（05 篇）这个心智，从"会话历史"复制到"系统提示词"上**——会话历史用 T1~T4 压，系统提示词用"分域+按需注入+淘汰"压，两者是同一套哲学的两个战场。

## 八、落地路线图（防过度设计）

不要一上来就全上，按真实规模演进：

| 阶段 | 现状 | 该做什么 |
|------|------|----------|
| **现在**（库小·就一两个话题） | 总纲才 8~14 条、几百 token | **什么都不用做**。分域反而是过度设计——一整块常驻完全 OK |
| **中期**（话题域涌现到 5~8 个） | 总纲开始变长、无关原则干扰 | 上**第一招归纳收敛** + **第二招分域按需注入**（收益最大） |
| **长期**（多品类·多校区·域 20+） | 热门域内部也变胖、有僵尸原则 | 补**第三招冷热淘汰** + 域的自动发现/合并 |

**判断信号**：当你发现"系统提示词里大量原则跟当前这句问话八竿子打不着"时，就是该上分域的时刻——在那之前，别急。

## 九、一句话总结

**"素材变多撑爆总纲"是个真问题，但它的根因不是样本数、而是"话题域数 × 全量常驻"。** 治理三招层层递进：

- **归纳即收敛**：同类合并、设条数上限，让总纲长成对数曲线而非线性堆叠。
- **分域 + 按需注入（核心）**：把总纲拆成话题抽屉，每轮只拉开当前问题相关的一两个 + 极短的全局铁律——**常驻税与总库大小彻底解耦**。
- **冷热淘汰**：热的留、冷的归档，让总纲是"活的"，长期维持健康规模。

配合样本库早已用的 top-k 检索，最终达成一句话的效果：**老师尽管放心教，库涨到几千条，每一轮进窗口的永远是"跟这句话有关的那一小撮"——又准、又省、又不失忆。**
