# AI 客服系统 —— 需求清单

> 课程演示项目。两个技术点:**Agent Loop(多工具自主决策)** + **自纠错/自进化闭环(转人工 → 人审知识补充 → 下次答对)**。
> 定位:麻雀虽小五脏俱全的**企业级可落地架构**,但大模型与数据用**可替换的桩**,方便课程现场离线演示。

## 一、项目定位与技术选型

| 项 | 选型 | 说明 |
| --- | --- | --- |
| 后端 | Python + FastAPI | Agent 生态成熟,演示代码清晰 |
| 大模型 | `LLMProvider` 抽象 + **Mock 实现** | 默认离线规则桩,可一行切换真实模型(OpenAI 兼容/国产/本地) |
| 向量库 | 本地实现(字符 n-gram + 余弦),SQLite 持久化 | 零外部依赖、离线可跑;可替换为 Chroma/pgvector |
| 存储 | SQLite | 零部署压力 |
| 前端 | 原生 HTML/CSS/JS 单页 | 聊天页 + 审核 tab,无需切命令行 |
| 场景 | 电商商品咨询 | mock 商品/订单/知识库数据 |

## 二、核心场景

电商商品咨询:客户在聊天窗口咨询商品参数、适用性、订单物流等;Agent 自主调用工具回答;遇到答不上的问题转人工,人工补充答案经审核后入库,系统下次即可自动答对。

## 三、两个技术点

### 技术点 ① Agent Loop(多工具自主决策)
- 核心循环:`推理 → 选工具 → 调用 → 观察结果 → 再决策 → 终止`
- 工具集:商品检索、知识库 RAG、订单查询、转人工
- 循环边界控制:最大步数、超时、防死循环(企业落地要点)
- 全程记录 Agent 轨迹(每步思考 / 工具 / 入参 / 出参),前端可视化

### 技术点 ② 自纠错 / 自进化闭环
- **触发**:Agent 自评"知识库未命中 / 没把握"时主动转人工;或用户明确要求转人工
- **工单**:把未解决问题 + 上下文存为工单
- **人工补充**:后台填写答案
- **审核队列**:人工答案先进待审,确认通过后才向量化入库(防知识污染)
- **进化体现**:同一问题"补充前走转人工 / 补充后直接答对";并提供知识库条目数、转人工率等统计佐证

## 四、功能模块

1. **Agent Loop 引擎**:循环、工具注册、边界控制、轨迹记录
2. **对话与展示界面**:聊天窗口 + 可视化思考过程 + 转人工状态提示
3. **自纠错闭环**:转人工触发、工单、人工补充、审核队列、知识入库
4. **数据与桩**:mock 商品 / 订单 / 初始知识库(含故意留空的问题)、LLM 抽象与 Mock
5. **演示支撑**:同一问题回放对比 + 简单统计看板

## 五、本期不做(后续可扩展)

- 多轮复杂对话记忆 / 用户画像
- 真实支付、下单
- 多租户、权限体系
- 失败案例驱动的 prompt 自动优化(作为"进阶展望"口头讲)

## 六、需求决策记录(本次确认结果)

- 技术栈:Python + FastAPI
- 大模型:Mock 抽象层(可切换)
- 界面:网页聊天页 + 可视化思考 + **审核 tab(本期确认加入)**
- 数据:mock 电商商品 + 本地向量知识库
- 侧重:两个技术点均衡,串成一个闭环故事
- 工具集:商品检索、知识库 RAG、转人工、订单查询
- 转人工触发:Agent 低置信度自评 + 用户主动要求
- 知识入库:人工填答 → 审核队列 → 确认入库
- 进化展示:同一问题回放对比(并附统计看板)
- 存储:SQLite + 本地向量库
