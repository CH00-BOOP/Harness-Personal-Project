项目八　商品销售数据模型微调与训练 —— SFT + DPO 全流程

角色:总体设计 + 核心研发。基于数据中台导出的语料微调豆包模型,让 AI 客服回复更像真人,再回灌到售前咨询 Agent(项目二)。

1. 设计数据分流策略:将中台 approved 的 ShareGPT/OpenAI 数据分为 SFT 数据(保留多轮上下文学销售话术风格)与 RAG 知识库数据(提炼课程/价格/优惠等结构化知识),践行「微调管风格、RAG 管知识」的职责分离,知识更新只改知识库、无需重训。
2. 采用两阶段训练策略:本地 LLaMA-Factory + Qwen2.5-3B-Instruct 做 QLoRA(rank=64, alpha=128, lr=2e-4)在单卡 RTX 4090 约 40 分钟一轮快速验证数据质量,通过后上传火山引擎方舟对豆包 1.5 做生产级 LoRA(rank=32, lr=1e-5),风格一致性人工盲评从 2.1 提升至 4.3(5 分制)。
3. 规划 SFT → DPO 训练路径:SFT 解决「从不会到会说」的风格模仿,DPO 对同一问题采样多条回复由销售主管标注 chosen/rejected 偏好对解决「会说但说不好」;选 DPO 而非 RLHF,因其跳过奖励模型训练、在偏好数据有限时更稳定且成本更低。
4. 构建三阶段 RAG Pipeline:Embedding 向量化 + 向量检索 top-20 粗召回,引入 Cross-Encoder 精排取 top-5,解决双编码器在语义相近文档上区分度不足的问题,知识命中率从 72% 提升至 89%。
5. 完成回路闭合:微调模型作为 LLM 层接入项目二 RTC 实时语音链路(客户语音 → ASR → RAG → 微调 LLM → TTS → 语音回复),通过微调缩短 system prompt 降低 TTFT,完成「数据中台 → 微调 → 客服」闭环。


四、架构影响力

1. 生态闭环设计:以数据中台为总线让各业务互相供数——原始数据 → 中台清洗 → 知识库/微调语料/素材/题库 → 客服/内容/考核多下游 → 结果与语料回流中台,真正实现「AI 的一切都是数据」。
2. 架构收口能力:从各业务独立造轮子演进到 MCP 协议共享服务集群,Agent 无状态、状态下沉共享服务,支撑规模化多业务低成本复用。
3. 性能与成本导向:在客服、直播、内容多个场景落地可量化的性能与成本收益(TTFT 15s→2s、检索 4 倍、存储降 75%、上传体积降 99%、推理成本降 40%、生成耗时降 70%)。
4. 工程判断力:清晰界定 Workflow 与 Agent 边界,能给出原型 → 生产的演进路径,并在合适时机克制地「不做」以规避过度设计。
