# AI Agent 系统架构师 / 高级 AI 应用工程师

> 主导设计并落地一套**以数据中台为底座、多 Agent 共享服务为骨架**的电商私域 AI 生态:从微信/直播原始数据的清洗沉淀,到 RAG 知识库、多模态素材、模型微调,再到实时语音客服、内容生成、销售考核的全链路闭环。技术范式对标 Claude Code,擅长在「模型自主决策」与「工程确定性护栏」之间做架构取舍。
>
> **核心方向**:Agent 运行时 / RAG 检索 / 多模态知识库 / 大模型微调 / LLM 推理链路优化 / AI 基础设施收口

---

## 核心技术能力

1. **Agent 与编排**:模型无关 Harness 底座、Agent Loop 自主决策循环、LangGraph 多阶段工作流(SubGraph / Checkpointer)、MCP 协议多 Agent 共享服务
2. **RAG 与向量检索**:HNSW 混合检索 + Int8 量化、Metadata 过滤、Rerank 精排(Cross-Encoder / base-rerank)、pgvector / Viking DB / Milvus 多租户隔离
3. **大模型工程**:LLM 网关与模型路由、Prefix Caching / KV Cache 深度优化、TTFT 首字延迟压缩、Token 配额与成本核算、QLoRA / LoRA 微调、SFT + DPO 偏好对齐
4. **多模态**:三模态统一向量底座、OCR(RapidOCR)+ VLM(qwen-vl)图片增强、ASR + LLM 视频摘要、文图视混排应答
5. **实时链路**:RTC 语音(ASR / TTS 情绪化回复 / 声音复刻)、FEC 前向纠错 + 自适应 Jitter Buffer 抗丢包
6. **数据工程**:ETL 数据流水线、多层脱敏引擎、对话块构建与预标注、多格式训练数据导出(ShareGPT / Alpaca / OpenAI JSONL / RAG CSV)
7. **工程化**:FastAPI · SSE 流式 · asyncio 并发 · PostgreSQL 任务队列 · Docker · 阿里云 Serverless(FC/SAE)· LangSmith / structlog 可观测 · SlowAPI 限流熔断

## 项目经历

### 项目一　AI 实时语音对话智能客服 —— 架构设计 + 核心研发

> 电商私域销售场景:将销售在微信/WhatsApp 的对话数据经中台清洗后建立 RAG 知识库,构建可实时语音对话的智能客服,承接「商品咨询 → 引导下单」全流程。

1. **RAG 知识库工程**:直接消费数据中台导出的 RAG 数据,采用**自定义标识符切片**解决语义截断,应用 **HNSW_HYBRID 混合检索 + Int8 量化**,构建 Metadata 标签过滤机制,存储空间**降低 75%**。
2. **多模态混排应答**:接入多模态素材中心(项目六),命中图片/视频等素材后以「文字 + 图片 + 视频」分条混排返回,让语音/图文客服具备多模态应答能力。
3. **语音场景检索调优**:通过降维 + 精简 Limit 策略引入 **base-rerank 轻量模型**,动态平衡 `dense_weight` 权重,在保持语义理解的同时显著提升专有名词命中率,**检索速度提升 4 倍**。
4. **LLM 推理链路极致优化**:固定 RAG 片段排序、合并 System Prompt 消息体,深度触发**前缀缓存(Prefix Caching)与 KV Cache**,将复杂 RAG 场景的**首字延迟(TTFT)从 15s 压缩至 2s 内**;并做模型选型与资源池优先级调优。
5. **RTC 语音链路优化(ASR/TTS)**:基于 ASR 实时捕获用户情感波动,配合 **TTS 声音复刻**实现情绪化回复;结合 **FEC 前向纠错 + 自适应 Jitter Buffer**,在 **50% 高丢包环境下实现语音对话无感知恢复**。
6. **提示词工程与数据回流**:基于 Prompt Pilot 管理提示词,构建评测集做自动化评分与版本对比;对负样本用智能优化算法重构提示词,高质量样本回流数据中台,为模型精调储备语料。
7. **微调模型接入**:接入微调后的模型作为 LLM 层(项目七),缩短 system prompt 进一步降低 TTFT;建立 **Max Token 分级控制模型**,按 95% 覆盖率边界动态配置推理/输出比例,提升单请求 Token 利用率。

### 项目二　AI 数据中台 —— 全链路数据流水线设计

> 整个 AI 体系的底座:客服 / 微调 / 考核 / 素材 / 直播等所有 AI 业务都从这里取数,把微信原始聊天记录加工成可训练、可检索、可考核的高质量数据资产。

1. **全链路数据流水线**:设计 `ETL → 原始库 → 暂存区 → 人工审核 → 多下游` 流水线,从微信本地 SQLite(MSG0-5.db + MicroMsg.db)抽取消息,完成 `wxid → 显示名`映射、群消息发送者解析、时间过滤与 `(session,timestamp,content)` 去重后落 `raw_chats` 不可变原始库。
2. **过滤 + 脱敏引擎**:构建 DataFilter,按 **9 级优先级**(系统/媒体/过短/敏感/闲聊/垃圾/高价值)分类丢弃噪声;对手机号、身份证、银行卡、邮箱、API Key 正则脱敏;设计**清洗时 + 写入时 + 导出时三重冗余脱敏**,并将**价格脱敏设为硬红线**,杜绝微调模型泄露真实定价。
3. **一键清洗与对话块构建**:基于 5 分钟时间窗切分会话、合并同角色连续消息、去重,并做自动预标注(分类 / 质量分 / Q&A 提取 / 敏感标记);高质量数据进 `staging_conversations` 暂存区,经人工 approve/reject/编辑后作为唯一可信数据源。
4. **多格式训练数据导出**:导出前二次清洗(价格脱敏、风格修复、过短过滤、过长截断、占位符清理),一份数据多格式导出 **ShareGPT / Alpaca / OpenAI JSONL**(供微调)与 **RAG CSV**(供知识库),打通项目七微调链路。
5. **向量知识库下游**:对 approved 数据做 embedding(DashScope text-embedding-v3)写入 `knowledge_chunks`,经 LLM 提炼为结构化 `knowledge_articles`(场景 / 客户话术 / 推荐回复 / 置信度),同时为项目一 RAG 检索与项目六 AI 考核出题提供素材。
6. **数据总线闭环**:中台对接全业务——项目五直播切片的 ASR 转写结果回流入库,项目六素材中心的图片/视频反向补充多模态语料,真正实现「AI 的一切都是数据」的闭环。

### 项目三　AI 直播切片 Agent —— 端到端 Agent 设计

> 直播带货场景:把直播回放交给 AI 自动找精彩片段、配标题文案,减轻剪辑师工作;转写结果同步回流数据中台复用。

1. **端到端三层架构**:设计「视频 → AI 找精彩片段 → 输出短视频切片」Agent,React 19 + FFmpeg.wasm 前端、FastAPI + SQLAlchemy 2.0 后端、Groq Whisper + DeepSeek 外部 AI。
2. **浏览器内 FFmpeg.wasm 提音频**:用 WORKERFS 零拷贝挂载源文件,转码为 16kHz/单声道/64kbps MP3,把 2.5GB 视频压到 ~30MB 再上传,**上传体积降低 99%**,用户等待从分钟级降到秒级。
3. **零云依赖任务队列**:用 PostgreSQL 构建任务队列,API 写入 pending 秒回,Task Runner 后台协程每秒抢占一条串行执行;进程崩溃时自动重置「进行中」任务回 pending,实现**零云依赖 + 崩溃可恢复**。
4. **可观测 Pipeline**:进度统一写库 + SSE 每秒读库推送,进度源唯一、断线可续、多端一致;长音频用 `ffmpeg -c copy` 按 25 分钟无损分段串行转录,时间戳加 offset 还原绝对时间轴。
5. **长视频 LLM 分析**:按 ~6000 token 分批 + 双向重叠去重(重叠 >30% 取高分项),支撑 **6 小时长视频不爆上下文**;内置直播/面试/讲座场景化 Prompt,按场景切换切片时长与去重阈值;输出爆款分、推荐文案与抖音风格标题、剪辑思路。
6. **导出复用**:导出阶段二次复用 FFmpeg.wasm 在浏览器内按 AI 时间段批量裁切打包 ZIP,后端不碰重型转码;ASR 转写结果回写数据中台留存。

### 项目四　自媒体智能内容运营 Agent —— LangGraph 工作流

> 电商需持续产出商品图、商品介绍、宣传文案,做一个内容生成 Agent 降本增效;产出图片直接关联素材中心,反哺多模态知识库。

1. **LangGraph 多阶段工作流**:用 **SubGraph** 将选题、写作、配图拆为独立编排单元;通过 **PostgreSQL Checkpointer** 持久化状态,支持任意历史节点回滚与增量重试,将故障恢复粒度从整图**细化到单节点**。
2. **全链路成本追踪**:设计 `MetricsContext` 上下文管理器采集各节点 Token 消耗、推理延迟、错误率,结合火山引擎定价模型完成成本核算,为模型选型提供数据支撑。
3. **SSE 流式输出**:与 LangGraph `astream_events` 深度集成,监听 `on_chat_model_stream` 捕获 Token 级实时流,配合前端 ReadableStream 将**感知 TTFT 降低 60%**,并保证流式/非流式下 Checkpointer 数据结构一致。
4. **配图异步并行**:`asyncio.gather` + `run_in_executor` 将同步 API 封装为协程并发执行,引入指数退避重试(1s→2s→4s)应对服务抖动,整体生成**耗时缩减 70%**。
5. **多模型动态路由**:简单任务走轻量 Flash、复杂任务走旗舰模型,配合 `with_structured_output` 做 Pydantic Schema 强约束,并用 JSON Mode + 手动解析解决结构化输出与 Token 统计不兼容问题,**降低 40% 推理成本**。
6. **Mock 开关体系 + 可观测**:环境变量驱动的 Mock 开关(llm/image/checkpointer)解耦外部服务,配合 Swagger UI 评测与 Ngrok 公网映射,本地调试**效率提升 3 倍**;接入 LangSmith + structlog + request_id,问题定位从小时级压缩到分钟级。
7. **容器化高可用**:SlowAPI 限流 + 熔断降级 + `/health` 健康检查 + 优雅关闭;生成商品图直接写入素材中心(项目六),经离线增强后成为 AI 客服多模态回复素材,形成「生成即沉淀」闭环。

### 项目五　基于 MCP 协议的多 Agent 共享服务集群 —— 架构收口

> 随 AI 项目增多,做架构层面统一收口:把 LLM 网关、RAG、记忆、Prompt 抽成共享基础设施,让所有业务(含数据中台)复用同一套底座。

1. **四大 MCP Server 抽离**:将 LLM 网关、RAG 检索、会话记忆、Prompt 管理抽为 4 个独立 MCP Server,经 **Streamable HTTP** 暴露标准化 Tool/Prompt 原语,新业务接入仅需写 Agent 编排层。
2. **REST → MCP 协议桥接网关**:基于 FastAPI 构建**四层中间件链**(认证 → 日志 → 配额 → 路由),Trace ID 全链路追踪;内置 MCP Client Manager 管理短连接,按项目维度做 API Key 认证与 Token 配额计量,保障多租户安全隔离与成本管控。
3. **统一 LLM 网关**:实现逻辑模型名 → Endpoint 路由(auto/pro/lite),YAML 配置热切换业务无感;Embedding 兼容火山引擎 text 与 vision 两种向量化路径,Token 消耗统一回传配额模块扣减。
4. **多租户 RAG 服务**:基于火山引擎 Viking DB 按 `project_id` 划分独立 Collection 做物理隔离,按 Markdown 标题层级 + 段落边界语义切分,新项目调 `ingest_document` Tool 即可自助接入。
5. **双层记忆架构**:对话记忆按 `project_id + session_id` 隔离支持最近 N 轮召回;用户画像按 `user_id` 跨项目共享,基于 PostgreSQL **UPSERT(ON CONFLICT DO UPDATE)幂等写入**,客服 Agent 自动提取用户事实(过敏/预算/偏好),写作 Agent 即时读取,实现跨项目用户认知同步。
6. **Prompt 模板中心**:基于 MCP 原生 Prompt 原语,YAML 定义参数 Schema、服务端渲染为 PromptMessage,模板修改即时生效无需重启,实现提示词工程与业务逻辑解耦。
7. **Agent 七步编排流水线**:`召回历史 → 读画像 → 检索知识 → 渲染 Prompt → LLM 推理 → 存记忆 → 提取事实`,全部经 GatewayClient 统一调用,**Agent 无状态、状态下沉共享服务**;各服务独立构建 Docker 镜像部署至阿里云 Serverless(FC/SAE),按拓扑分层发布、灰度 + 秒级回滚,SIGTERM 优雅终止保障在途请求不丢。

### 项目六　多模态素材中心 & AI 销售考核系统 —— 一条数据线两大能力

> 素材中心统一管理商品图/详情/视频,为 AI 客服提供多模态回复能力并补充数据中台;中台导出的高质量知识又驱动 AI 销售考核,替代人工培训。

**A. 多模态素材中心(图片/视频 → 可被语义命中的多模态知识库)**

1. **三模态统一向量底座**:设计 `rag_assets` 表,text/image/video 三模态共用一张表(pgvector 1024 维 + HNSW `vector_cosine_ops`),一条 SQL 跨模态召回;核心理念是**不向量化媒体本身,而向量化其检索文本** `retrieval_text`(「这张图/视频能回答什么问题」),与用户提问天然对齐。
2. **人工即时命中(manual)**:图片/视频上传时人工维护标题/描述/标签/分类,拼接为 `retrieval_text` 经 text-embedding-v3 入库即可被命中;隐私红线为命中返回**打码版 TOS URL**。
3. **离线机器增强(enriched)**:在同一行上用 **OCR(RapidOCR)+ VLM(qwen-vl)** 补图片文字与看图描述、用 **ASR + LLM 摘要**补视频口播,人工内容在前、机器内容追加,重写 `retrieval_text` 并重新 embedding,**召回相似度从 ~0.38 提升至 ~0.71**;按 `(source_table, source_id)` UPSERT 幂等可反复回扫。
4. **长视频分段与混排**:长视频按 ASR 时间戳分段为多条 `rag_assets`,`media_url` 携带 `#t=秒数`,命中后前端播放器直接跳转精彩片段;统一应答按「文字必发、图 ≤3、视频 ≤1」混排,阈值递增(text 0.35 < image 0.40 < video 0.42)。

**B. AI 销售考核系统(替代人工培训与考核)**

5. **LLM 自动出题**:消费数据中台产出的 `knowledge_articles/knowledge_chunks`,按场景分类 + 置信度取素材,以「资深考官」角色(temperature 0.7)生成简单/中等/困难分级的开放式场景题与参考答案。
6. **LLM 自动评判**:以「资深评审专家」角色(temperature 0.3 保稳定)从实战性、需求把握、销售策略、话术自然度、红线检查**五维度**逐题打分,按「平均分 ×10」映射百分制,支持人工二次复核校准。
7. **RAG 出题演进**:针对知识库膨胀到十万级,设计 RAG 出题方案——模糊请求先由 LLM 规划主题 → 多轮向量检索(pgvector/Milvus)→ **MMR 去重保多样性**,解决固定 top-30 导致题目重复、长尾素材浪费的问题。

### 项目七　基于聊天数据的大模型微调 —— SFT + DPO 全流程

> 为让 AI 客服回复更像真人,基于数据中台导出的 SFT/DPO 数据微调豆包模型,再回灌到项目一的客服系统。

1. **微调语料来自中台**:消费中台 approved 的 ShareGPT/OpenAI 数据,分流为两套——**SFT 数据**(保留多轮上下文学销售话术风格)与 **RAG 知识库数据**(提炼课程/价格/优惠等结构化知识),践行「**微调管风格、RAG 管知识**」的职责分离,知识更新只改知识库无需重训。
2. **两阶段训练策略**:「本地小模型验证 + 云端大模型训练」——本地 LLaMA-Factory + Qwen2.5-3B-Instruct 做 **QLoRA**(rank=64, alpha=128, lr=2e-4),单卡 RTX 4090 约 40 分钟一轮快速验证数据质量;通过后上传火山引擎方舟对豆包 1.5 做生产级 **LoRA**(rank=32, lr=1e-5),按模型规模等比缩放超参,**风格一致性人工盲评从 2.1 提升至 4.3(5 分制)**。
3. **SFT → DPO 两阶段路径**:SFT 解决「从不会到会说」的风格模仿;**DPO** 对同一问题采样多条回复,由销售主管标注 chosen/rejected 偏好对,解决「会说但说不好」;选 DPO 而非 RLHF 是因其跳过奖励模型训练,在偏好数据有限(几百条)时**更稳定、成本更低**。
4. **三阶段 RAG Pipeline**:`Embedding → 向量检索 → Rerank`——火山引擎 Embedding 向量化 + 向量检索 top-20 粗召回,引入 **Cross-Encoder 精排取 top-5**,解决双编码器在语义相近文档上区分度不足问题,**知识命中率从 72% 提升至 89%**。
5. **回路闭合**:微调模型作为 LLM 层接入项目一 RTC 实时语音链路(`客户语音 → ASR → RAG → 微调 LLM → TTS → 语音回复`),通过微调缩短 system prompt 降低 TTFT,完成「**数据中台 → 微调 → 客服**」的回路闭合。

### 项目八　AI 课程咨询 Agent 系统 —— 模型无关 Agent 运行时底座(Harness)

> 从零设计并实现**模型无关、工具可插拔的 Agent 运行时底座(Harness)**,支撑可自主决策、自我进化的智能客服 Agent,架构范式对齐 Claude Code。

1. **Harness 底座(模型无关/工具可插拔)**:以 `LLMProvider` + `Tool` 双抽象 + 注册表解耦,Loop 引擎只依赖接口;新增模型仅写一个 `chat()` 适配器、新增能力仅登记一个 `Tool`,循环与业务代码零改动;配置驱动在离线 Mock 与真实豆包间热切换,内部 `tool_call/tool_result` 协议与主流 function calling 同构。
2. **Agent Loop(模型自主决策)**:实现「推理 → 选工具 → 调用 → 观察 → 再决策 → 终止」闭环,**决策权完全交给模型、意图识别隐式融入工具选择**(去除独立意图分类模块);支持单步多工具并行;工具异常转 observation 回填由模型**自纠错**而非中断;最大步数 + 超时双重护栏,超限自动转人工;全链路 Trace 可视化。
3. **AI 自进化(示范学习替代微调)**:业务专家以「问题 + 答案 + 套路原因」对话式教学 → 样本入库 → LLM 自动归纳「套路总纲」注入提示词,**改完即时生效**;服务时向量 top-k 召回样本语义精判,换问法/相似意图自动命中,没把握则转人工;支持「答不上 → 工单 → 补充 → 下次答对」与点评式纠偏一键固化;提示词分层治理(业务铁律 > 总纲 > 召回话术)保障报价等高风险动作可控。
4. **上下文工程(对标 Claude Code)**:以「预算账户」而非「容器」建模,追求信噪比、规避 context rot;架构**已内含三重管理**——会话剥离工具噪声、总纲对样本的语义压缩、recall 的 top-k 按需检索;规划分层压缩(T1 删/T2 搬/T3 折叠客户画像/T4 结构化会话档案)+ 关键事实外部存储双写兜底;并能界定子 Agent 适用边界、按当前规模判定暂不引入以避免过度设计。

## 架构亮点总览

1. **生态闭环**:七大业务以数据中台为总线互相供数——`微信/直播原始数据 → 中台清洗 → RAG 知识库 + 微调语料 + 素材 + 考核题库 → 客服/内容/考核多下游 → 结果与语料回流中台`,真正实现「AI 的一切都是数据」。
2. **架构收口能力**:从各业务独立造轮子,演进到 MCP 协议共享服务集群(LLM 网关 / RAG / 记忆 / Prompt),Agent 无状态、状态下沉,支撑规模化多业务复用。
3. **性能与成本极致优化**:TTFT 15s → 2s、检索速度 4 倍、存储降 75%、上传体积降 99%、推理成本降 40%、生成耗时降 70%,兼顾体验与成本。
4. **克制的工程判断**:清晰界定 Workflow 与 Agent 边界,能明确原型 → 生产的演进路径,知道何时「不做」以规避过度设计。
