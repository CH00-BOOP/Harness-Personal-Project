# AI 客服系统 —— 演示用例(自纠错 / 自进化)

> 现场照着这个脚本问即可。每个用例标注了:输入、预期 Agent 行为(工具调用)、预期结果。
> 演示主线:**Agent Loop 多工具自主决策** + **自纠错闭环(转人工→人审补充→下次答对)** + **自进化(知识库增长、转人工率下降)**。

---

## 第一幕:Agent Loop —— 单工具自主决策

**用例 1.1 商品参数查询**
- 输入:`颐养老人手机的电池能用多久?`
- 预期轨迹:`product_search(颐养老人手机)` → 命中商品参数 → 直接回答
- 预期结果:答出电池/续航参数。
- 看点:Agent **自己决定**调用商品检索工具,无需写死流程。

**用例 1.2 订单物流查询**
- 输入:`我的订单 ORD10001 到哪了?`
- 预期轨迹:`order_query(ORD10001)` → 返回物流状态 → 回答
- 看点:不同问题,Agent 选择了**不同的工具**。

---

## 第二幕:Agent Loop —— 多步推理 + 多工具

**用例 2.1 适用性咨询(需检索 + 推理)**
- 输入:`这款手机适合送长辈吗?`(指颐养老人手机)
- 预期轨迹:`product_search` 拿到参数(大字体/大音量/超长待机) → `knowledge_base` 查适用建议 → 综合推理 → 回答"适合,因为……"
- 看点:**一次对话里调用多个工具 + 组合推理**,这是 Agent Loop 区别于传统 FAQ 的核心。

---

## 第三幕:自纠错闭环(核心)★

**用例 3.1 触发转人工(知识缺口)**
- 输入:`扫地机器人 X1 能翻越多高的门槛?`
- 预期轨迹:`product_search` 商品存在但无该参数 → `knowledge_base` 未命中(分数低于阈值) → Agent 自评没把握 → `handoff` 转人工
- 预期结果:回复"这个问题我暂时没把握,已为您转接人工客服处理"。
- 后台:审核 tab 的"待处理工单"出现该问题。

**用例 3.2 人工补充 + 审核入库**
- 操作:在审核 tab 给工单填写答案:`扫地机器人 X1 可自动翻越最高约 2cm 的门槛。`
- 操作:在审核队列点击"通过" → 知识向量化入库。
- 看点:**人审关卡防止知识污染**,贴近真实企业方案。

**用例 3.3 回放验证(自纠错生效)★**
- 输入(再次):`扫地机器人 X1 能翻越多高的门槛?`
- 预期轨迹:`knowledge_base` 命中(刚入库的知识) → 直接回答 `约 2cm`
- 看点:**同一个问题,补充前转人工 / 补充后秒答**——最直观的自纠错证据。

---

## 第四幕:自进化(系统越用越好)

**用例 4.1 第二个知识缺口**
- 输入:`蓝牙耳机 Air 防水吗?`
- 预期:`knowledge_base` 未命中 → 转人工。
- 补充答案:`蓝牙耳机 Air 支持 IPX4 级生活防水,可防汗防小雨,不可水洗。` → 审核通过入库。
- 再问:`蓝牙耳机 Air 防水吗?` → 直接答出 IPX4。

**用例 4.2 统计看板对比(量化进化)**
- 打开统计看板,观察:
  - 知识库条目数:种子 N 条 → 经过 3.x / 4.1 后 N+2 条(**知识在增长**)
  - 转人工率:随知识补充逐步下降(**系统在自我改善**)
- 看点:不仅"看得见"个案,还能用**指标量化**系统进化。

## 演示动线建议(5 分钟版)

1. 用例 1.1 / 1.2 —— 秀 Agent 自主选工具
2. 用例 2.1 —— 秀多工具 + 推理
3. 用例 3.1 —— 答不上,自动转人工
4. 切审核 tab:3.2 填答案 + 审核入库
5. 用例 3.3 —— 同一问题这次秒答(高潮)
6. 用例 4.2 —— 看板展示转人工率下降,收尾"系统会自进化"

## 预置数据约定(种子数据需配合)

- 商品:`颐养老人手机`(大字体/大音量/4000mAh 超长待机)、`旗舰拍照手机 Pro`、`蓝牙耳机 Air`、`扫地机器人 X1`
- 订单:`ORD10001`(运输中)、`ORD10002`(已签收)
- 种子知识:退换货政策、发货时效、老人机适用建议等
- **故意留空**:扫地机器人门槛高度、蓝牙耳机防水等级(用于演示自纠错)
