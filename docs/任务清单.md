## 数据模型(SQLite 表)

- `tickets`:转人工工单(id, question, context, status, created_at)
- `kb_audit`:知识审核队列(id, ticket_id, question, answer, status, created_at)
- `knowledge`:已入库知识(id, question, answer, vector, created_at)
- `metrics_log`:每次会话埋点(id, session_id, asked, hit_kb, handoff, created_at)

## 接口清单

- `POST /api/chat` 发消息,返回最终回复 + Agent 轨迹
- `GET  /api/tickets` 待处理工单列表
- `POST /api/tickets/{id}/answer` 人工补充答案 → 进审核队列
- `GET  /api/audits` 审核队列
- `POST /api/audits/{id}/approve` 审核通过 → 入库
- `POST /api/audits/{id}/reject` 审核驳回
- `GET  /api/metrics` 统计看板(知识库条目数、转人工率等)

## 验收标准

1. 启动后浏览器打开聊天页,问商品参数能自动调工具回答(轨迹可见)。
2. 问 KB 未覆盖的冷门问题 → 自动转人工。
3. 审核 tab 能看到工单 → 填答案 → 审核通过 → 入库。
4. 重新问同一问题 → 直接答对(不再转人工)。
5. 统计看板能看到入库前后转人工率变化。
